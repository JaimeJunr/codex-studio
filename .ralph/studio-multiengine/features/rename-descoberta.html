Rename e descoberta

Feature Overview

O nome codex-studio amarra o projeto a um fornecedor que já não é o único motor — e o upstream fez o mesmo movimento primeiro, saindo de cursor-mcp-bridge para polyagent-mcp. Esta feature troca o nome, executa o rename sem deixar referência órfã, e escreve as descrições para que o projeto seja encontrado por quem procura o problema que ele resolve.

Vem por último de propósito: toca os mesmos arquivos que as features 1 e 2 editam, incluindo as 46 invocações cruzadas <plugin>:<skill> em 13 SKILL.md.

User Stories

US-011 Ready decisão

Como dono do projeto, quero escolher o nome contra critérios explícitos e disponibilidade verificada, para que a escolha não dependa de gosto nem produza colisão.

  • AC: O nome não contém o nome de nenhum fornecedor ou motor (codex, grok, cursor, claude, openai, xai).
  • AC: O nome funciona como prefixo dos 11 plugins sem ficar desajeitado: <nome>-image, <nome>-deck, <nome>-sprite.
  • AC: Verificada a ausência de colisão relevante em GitHub, npm e PyPI, e a ausência de produto comercial homônimo no mesmo espaço (geração visual / IA / ferramenta de dev).
  • AC: O nome é pronunciável e tem grafia única — quem ouve consegue escrever.
  • AC: A escolha final é do usuário; esta US entrega candidatos verificados, não decide sozinha.
US-012 Blocked · US-011, US-007 repo inteiro

Como mantenedor, quero o rename executado sem deixar referência órfã, para que a cadeia de dependência entre plugins continue funcionando.

  • AC: Renomeados os 11 diretórios plugins/codex-*, os 11 plugin.json (name, description, keywords, homepage, repository) e as entradas do marketplace.json.
  • AC: As 46 invocações cruzadas codex-X:skill em 13 SKILL.md apontam para os IDs novos — incluindo as dependências reais que sustentam a arquitetura: codex-image:generate consumido por 6 skills downstream, codex-deck por 2, e a herança de codex-sprite:sprite pelos três especialistas de estilo.
  • AC: Uma varredura por codex-(image|deck|social|infographic|biz|study|web|sprite|pixel|cartoon|realistic) retorna vazia fora do CHANGELOG.
  • AC: Uma varredura por invocação <plugin>:<skill> apontando para plugin inexistente retorna vazia — é este o critério que distingue "renomeado" de "renomeado sem órfão".
  • AC: Sem alias de compatibilidade. O CHANGELOG registra a quebra e instrui a reinstalação com os IDs novos.
  • AC: O CLAUDE.md do projeto reflete os nomes novos — ele descreve a arquitetura por ID de plugin em várias seções.
US-013 Blocked · US-011, US-009 docs + metadados

Como pessoa com o problema que este projeto resolve, quero encontrá-lo buscando pelo problema, para não precisar já saber o nome dele.

  • AC: A descrição do repositório e os GitHub topics carregam os termos pelos quais o problema é buscado — geração de imagem sem API key, plugin de Claude Code, pixel art, sprite sheet, deck a partir de prompt — em vez de descrever a arquitetura interna.
  • AC: Cada um dos 11 plugin.json tem description e keywords que descrevem o que aquele plugin faz para o usuário, não como ele foi construído.
  • AC: O README abre dizendo o que o projeto faz e para quem, com o diferencial keyless na primeira tela — não depois da seção de instalação.
  • AC: Os termos escolhidos são os que uma pessoa realmente digitaria, verificados contra busca real e não inventados no escritório.

Functional Requirements

  1. O nome escolhido é validado contra os critérios da US-011 antes de qualquer arquivo ser tocado — a verificação de colisão precede o rename.
  2. O rename é atômico em uma única mudança: diretórios, plugin.json, marketplace.json e invocações cruzadas migram juntos, porque um estado intermediário quebra a resolução de plugin em runtime.
  3. A conclusão do rename é definida por duas varreduras vazias — nenhum ID antigo fora do CHANGELOG, e nenhuma invocação <plugin>:<skill> apontando para plugin inexistente.
  4. Os termos de descoberta são escolhidos a partir de busca real, não inventados; o nome carrega distinção e os metadados carregam as palavras-chave.

A lição é mais útil que a lista: palavra única de dicionário no espaço visual/IA está toda tomada, e o espaço adjacente a Claude Code está sendo ocupado agora. Nome bonito e genérico perde nas duas pontas — colide e não ranqueia.

i
Onde o SEO realmente mora. O nome não precisa carregar as palavras-chave; a descrição e os topics carregam. O nome precisa ser distintivo o bastante para ranquear sozinho quando alguém lembrar dele — o que empurra para um nome de baixa competição, não para um nome descritivo e disputado. Tratar as duas coisas como trabalhos separados: nome distintivo (US-011), termos buscáveis nos metadados (US-013).
